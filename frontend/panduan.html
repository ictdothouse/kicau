Web Development · Panduan Bahagian 1

Bina Kicau, app mikroblog pertama anda

Anda akan jalankan Kicau, sebuah app gaya Threads, dan faham bagaimana tiga fail HTML, CSS dan JavaScript bercakap dengan pangkalan data sebenar di internet.

Anda perlukan
Browser (Chrome, Edge atau Firefox) dan text editor (VS Code atau Notepad)
Tiada install
Tiada npm, tiada server. Hanya buka fail.
Anda akan belajar
fetch(), JSON, DOM, event dan SQL asas

01Apa yang kita bina

Kicau membolehkan semua orang dalam kelas menulis post pendek, menekan like dan membalas post orang lain. Semua post disimpan dalam satu pangkalan data. Apabila rakan anda post sesuatu, anda nampak post itu selepas menekan Muat semula.

Anda edit ini

index.html, style.css, app.js

API

Cloudflare Worker, alamat /api/posts

SQL⟶⟵baris data
Data disimpan di sini

Database

Cloudflare D1, table posts

Kenapa perlu API di tengah?

Untuk membaca atau menulis pangkalan data, program perlukan kunci rahsia (token). Jika kunci itu diletak dalam app.js, sesiapa sahaja boleh tekan F12, salin kunci itu dan padam semua data. Jadi kunci disimpan di server (API) sahaja. Browser anda hanya boleh meminta perkara yang API benarkan: senarai post, post baru, like dan reply.

Nota

Hampir semua app web ikut corak ini: frontend → API → database. Instagram, Shopee dan Threads pun sama.

02Persediaan

  1. Dapatkan folder frontend daripada pensyarah, atau dari GitHub: klik Code → Download ZIP, kemudian extract.
  2. Buka app.js dengan text editor. Pada baris 6, pastikan URL ialah URL API yang diberi pensyarah.
  3. Double-click index.html. App terbuka dalam browser.
  4. Taip nama anda, tulis sesuatu dan tekan Post. Post anda muncul di atas senarai.
Jika gagal

Jika keluar mesej Gagal muat post, lihat bahagian 11, Masalah biasa.

04Cuba API terus dalam browser

Sebelum membaca kod, lihat dahulu data yang app terima. Buka tab baru dan taip URL API ditambah /api/posts:

Anda akan nampak teks seperti di bawah. Ini JSON, format teks untuk menghantar data antara program. Tanda [ ] ialah senarai, dan { } ialah satu objek (satu post).

MedanMaksud

Senarai API

KaedahAlamatFungsi
GET/api/postsAmbil 50 post terbaru
POST/api/postsCipta post. Hantar {"username": "ali", "content": "hai"}
POST/api/postsCipta reply. Tambah "parent_id": 1
GET/api/posts/1/repliesAmbil semua reply bagi post 1

GET bermaksud minta data. POST bermaksud hantar data atau buat perubahan. Bar alamat browser hanya boleh buat GET; POST dihantar oleh JavaScript.

Intip dengan DevTools

  1. Dalam app Kicau, tekan F12 dan pilih tab Network.
  2. Klik penapis Fetch/XHR supaya hanya permintaan API dipaparkan.
  3. Tekan butang Muat semula dalam app. Satu baris bernama posts muncul. Klik baris itu, kemudian pilih tab Response.
  4. Tekan ♡ pada mana-mana post. Permintaan baru bernama like dengan kaedah POST muncul.

05index.html: rangka halaman

  • required dan maxlength ialah validasi terbina dalam browser. Browser tidak akan hantar borang jika nama kosong.
  • <ul id="feed"> sengaja dibiarkan kosong. JavaScript akan mengisinya dengan post.

Kandungan dalam <template> tidak dipaparkan. Ia sebuah acuan: setiap kali app.js perlu memaparkan satu post, ia menyalin acuan ini dan mengisi nama serta isi post.

<script src="app.js"> diletak di hujung <body>, supaya semua elemen sudah wujud ketika JavaScript mula berjalan.

06style.css: rupa

Warna ditulis sekali sebagai pemboleh ubah (--bg, --fg). Apabila komputer pengguna dalam mod gelap, hanya nilai pemboleh ubah ditukar. Peraturan lain kekal sama.

Apabila #feed tiada isi, CSS sendiri memaparkan mesej. Tiada JavaScript diperlukan.

07app.js: otak app

7.1 Fungsi api(): bercakap dengan server

  1. fetch() menghantar permintaan ke API + path, contohnya …/api/posts.
  2. await menunggu jawapan sampai tanpa membekukan halaman. Sebab itu fungsi ditanda async.
  3. JSON.stringify(body) menukar objek JavaScript kepada teks JSON untuk dihantar.
  4. res.json() menukar teks JSON yang diterima kembali kepada objek JavaScript.
  5. Jika server balas status gagal (contoh 400), throw menghantar mesej ralat server kepada blok catch yang memanggil fungsi ini.

Satu fungsi ini dipakai untuk semua permintaan: api('/api/posts') untuk ambil senarai, dan api('/api/posts', 'POST', {...}) untuk hantar post baru.

7.2 renderPost(): tukar data kepada HTML

cloneNode(true) menyalin acuan <li> dari <template> beserta semua elemen di dalamnya. Kemudian setiap bahagian diisi dengan data post.

Keselamatan

Sentiasa guna textContent, bukan innerHTML, untuk teks yang ditaip pengguna. Cuba post <b>hai</b>: ia dipaparkan sebagai teks biasa. Dengan innerHTML, browser akan menjalankan apa-apa HTML atau skrip yang ditaip orang lain. Serangan ini dipanggil XSS.

7.3 loadFeed(): papar semua post

posts.map(renderPost) menukar senarai data kepada senarai elemen <li>. replaceChildren() membuang kandungan lama dan memasukkan yang baru sekali gus.

7.4 Hantar post baru

  • event.preventDefault() penting. Tanpa baris ini, browser akan reload halaman apabila borang dihantar, mengikut tingkah laku asal borang HTML.
  • Butang dimatikan (disabled) semasa menunggu, supaya klik dua kali tidak menghantar post berganda.
  • localStorage mengingat nama anda dalam browser untuk lawatan seterusnya.

7.5 Like

Setiap butang ♡ ada event listener sendiri yang ingat post.id miliknya. Server membalas bilangan like terkini, dan nombor itu dipaparkan.

08Apa berlaku bila anda tekan Post

  1. Browser menjalankan fungsi submit dalam app.js.
  2. api() menghantar POST ke /api/posts bersama {"username": "ali", "content": "hai"}.
  3. API menyemak data: nama 1 hingga 30 aksara, post 1 hingga 500 aksara. Jika tidak sah, API balas ralat 400.
  4. API menjalankan SQL INSERT INTO posts … dalam D1.
  5. D1 menyimpan baris baru dan memberinya id.
  6. API membalas JSON post baru dengan status 201 (Created).
  7. app.js memanggil loadFeed(), yang meminta senarai terkini dan melukis semula halaman.

09Database: table posts

Semua data Kicau berada dalam satu table bernama posts di Cloudflare D1. D1 menggunakan SQL, bahasa yang sama dipakai oleh MySQL dan PostgreSQL.

Reply juga disimpan dalam table yang sama. Bezanya, reply ada parent_id yang menunjuk kepada id post asal.

SQL yang dijalankan oleh API

Kenapa tanda ?

Tanda ? ialah tempat kosong. API mengisi nilai sebenar secara berasingan, jadi teks yang ditaip pengguna tidak boleh mengubah arahan SQL. Ini menghalang serangan SQL injection.

10Latihan

Semua latihan hanya mengubah fail dalam folder frontend. Selepas setiap perubahan, simpan fail dan tekan Ctrl + F5 dalam browser.

1. Tukar warna like Mudah

Jadikan butang like berwarna biru apabila ditekan.

Petunjuk

Dalam style.css, cari pemboleh ubah --like dalam :root.

2. Tarikh penuh bila hover Mudah

Apabila tetikus berada di atas "5 minit lalu", paparkan tarikh dan masa penuh.

Petunjuk

Atribut HTML title memaparkan teks semasa hover. Tambah satu baris dalam renderPost():

3. Auto-refresh Sederhana

Muat semula senarai post setiap 10 saat secara automatik. Selepas berjaya, buka reply pada satu post dan tunggu 10 saat. Apa berlaku, dan kenapa?

Petunjuk

Bahagian reply tertutup kerana loadFeed() membuang semua <li> dan membina semula dari acuan.

4. Butang salin Sederhana

Tambah butang Salin pada setiap post yang menyalin isi post ke clipboard.

Petunjuk

Tambah butang dalam <div class="actions"> dalam templat, kemudian beri ia event listener dalam renderPost():

5. Had 280 aksara Mencabar

Tukar had post daripada 500 kepada 280 aksara. Kemudian buka Console (F12) dan jalankan arahan di bawah. Adakah post 300 aksara itu berjaya? Apa maksudnya untuk keselamatan app?

Petunjuk

Ubah maxlength="500" dalam index.html dan teks /500 dalam app.js. Post 300 aksara tetap berjaya kerana API masih membenarkan 500. Validasi dalam browser boleh dipintas oleh sesiapa. Server mesti sentiasa menyemak semula data.
